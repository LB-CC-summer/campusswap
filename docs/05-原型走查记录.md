## 二、四种异常态专项检查

需求文档 7.8 要求每个数据页都要有「加载中 / 空结果 / 接口失败 / 能力降级」四态。原型层面的核查结果：

| 异常态 | 是否已在原型体现 | 走查结论 | 建议 |
|---|---|---|---|
| **加载中** | ❌ 未画 | 设计稿通常不画加载态，可接受 | 实现阶段统一用骨架屏（不用转圈，避免页面跳动）。此项由前端在代码中兜底，不要求 UI 出图 |
| **空结果** | ❌ 未画 | 集市「筛选无结果」、找物「硬条件无命中」都没有对应画面。**这是 AC-05 的证据缺口**——验收要看"无结果时不拿别的商品凑数、并给出三条出口" | 补 2 帧：① 集市筛选空态（含「不限校区 / 关闭邮寄筛选」按钮）② 找物无结果（含「改为不限校区 / 放宽预算 / 保存求购」） |
| **接口失败** | ❌ 未画 | 全站无「请求失败 + 重试」画面 | 补 1 帧通用错误态（含重试按钮 + 不丢失筛选条件的说明） |
| **能力降级（智能体不可用）** | ✅ 已画 | 做得最好的一处：`智能体服务失败` → 「重试 / 普通搜索 / 手动发布」三个出口，比需求文档要求还多一个 | 保持；建议在 README 里点名这一帧，作为 AC-13 的直接证据 |

**小结**：四态里只落地了 1 个（能力降级），空结果与接口失败是最需要补的两帧。

## 四、走查复现步骤（供他人复核）

1. 用**无痕窗口**打开 proto 链接（不清 Cookie 会看到别人的登录态，结论不准）。
2. 确认右上角显示 `Log in or create account`——说明当前是未登录的访客视角，与助教视角一致。
3. 用底部 `Previous frame / Next frame` 逐帧翻页，再用鼠标点击页面内热区（商品卡、咨询卖家、对比、智能找物 banner）。
4. 每页截图存档，命名 `序号-页面名.png`，供 `docs/prototype/screens/` 使用。
5. 若点击无响应，先确认该处是否真的画了热区——Figma 里漏连热区时，点击会停在原页面。

> 已归档的走查截图：11 张前台 + 1 张后台概况（见交付包 `原型截图/`）。

## 五、给 UI 的修改清单（可直接执行）

按优先级排，做完前 3 条即可满足答辩验收：

1. **补「找物推荐结果」帧**：4 个条件标签 + 2~3 张推荐卡片（每张带「符合什么」绿标签、「缺什么」橙标签）+ 顶部一句推荐理由。
2. **补「集市空态」与「找物无结果」两帧**，各带 2~3 个出口按钮。
3. **补后台 4 个子页**（用户/商品/校区/举报），重点画状态矩阵：`强制下架` 在售=可点 / 交易中=置灰带提示 / 已下架=消失；`禁用↔解禁` 按行状态互斥显示。
4. 删掉集市里那张「已预订」卡片。
5. 商品卡补履约方式：`大学城 · 在售 · 仅面交`。
6. 交易中心撤掉「接受 / 拒绝」，卖家端只留「确认完成」。
7. 联系方式交换补「待对方同意」「已同意」「已关闭」三张小图。
8. 给 Flow 改个名字（如「主流程：找物 → 详情 → 咨询」）并补一句描述。
