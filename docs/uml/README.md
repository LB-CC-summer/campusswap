# UML 与架构图

本目录存放《校易集 CampusSwap 系统设计说明书》引用的全部图形。每张图同时提交 `.puml` 源文件与 `.png` 导出图，两者同名同目录。

## 命名规范

- 文件名格式：`序号-语义名.puml` / `.png`，序号两位数，语义名全小写、连字符分隔
- PNG 导出要求：宽度不小于 1600px，`dpi` 不低于 200，图中不得出现模糊文字
- 提交时 `.puml` 与 `.png` 必须一并提交，只交 PNG 无法修改

## 跨图一致性约定

以下三点在不同图中会重复出现，必须口径一致，否则评审对照时会被认定为前后矛盾：

1. **并发抢单场景的参与者固定为五个**：买家 A、买家 B、TradeService、`trade` 表、`product` 表。时序图（06）与协作图（07）必须使用同一组生命线，否则两张图对不上。
2. **交易状态枚举固定为六个值**：`confirmed`（已确认）、`completed`（已完成）、`cancelled`（已取消）、`aborted`（已中止）四个为实际产生值，`pending`（待确认）、`rejected`（已拒绝）为保留值、本期不产生。先到先得口径下不存在「待确认」环节。
3. **商品状态枚举固定为五个值**：`draft`（草稿）、`on_sale`（在售）、`reserved`（已预订）、`sold`（已售出）、`off_shelf`（已下架）。
