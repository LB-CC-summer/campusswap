## 四、执行顺序（谁阻塞谁）

一句话：**库和壳先定，认证先通，商品后通，页面最后接，材料线全程并行。**

关键路径共 6 步，串行，压缩不了：① 库导入 + 后端骨架 → ② 统一壳 + 本期契约冻结 → ③ 登录/JWT → ④ 商品发布与列表 → ⑤ 前端页面接通 → ⑥ 上线验收。

两条支线提前并行：**部署线**（服务器/解析/证书）从 11/26 起就要动，但"验收上线"卡在 ⑤；**智能体线**前半段（工具 schema、提示词、mock）11/26 起就能写，真实返回卡在 ④。

### 4.1 硬依赖（倒过来做必返工）

| 前置 | 阻塞谁 | 为什么不能倒 |
|---|---|---|
| `schema.sql` 导入 + `seed.sql` | 全部后端接口 | 无库无数据，接口只会返回空数组，前端接上也看不出对错 |
| 统一返回壳（`core/response.py`） | 全部接口 + 前端 `request.ts` | 壳一改，前端拆包、错误提示、所有页面一起返工 |
| 03 文档锁定本期字段 | 前端 mock 与后端实现 | A-05 的前提；不锁就只能边写边猜 |
| 登录 / JWT | 发布、我的信息 | `seller_id` 从 token 取，没 token 连商品都发不了 |
| 图片上传接口 | F06 发布页整页 | 没有上传，发布页只剩一个填不进图的表单 |
| 商品列表接口 | F02 集市、`search_products` 工具 | 列表是检索底座，工具直接复用同一段 SQL |
| 组件基线（卡片/按钮/空态） | 胡俐伶的两页 | 两人各写一套样式，最后合不成一个视觉 |
| 域名解析生效 | HTTPS 证书签发 | 校验要解析先通，11/29 当天才做 DNS 一定来不及 |
| 冲刺计划博客（11/27 发布） | 冲刺总结 | 要求原文点名"附带冲刺计划的链接" |
