# 文档构建工具

把 `docs/` 下的 Markdown 交付物排版成符合国标格式的 PDF。本机没有 pandoc，
因此采用 `Markdown → DOCX（python-docx）→ PDF（Word）` 两段式。

## 依赖

| 组件 | 用途 | 本机情况 |
|---|---|---|
| Python 3 + python-docx | 生成 DOCX、控制排版 | 已具备 |
| Microsoft Word | 更新目录域、导出 PDF、生成书签 | 已具备（Office16） |

无需 pandoc，无需 LaTeX。Word 缺失时第二步无法完成，但 DOCX 仍可生成。

## 用法

```bash
# 1. Markdown → DOCX（--toc 生成目录页）
python tools/md2docx.py docs/01-系统设计说明书.md docs/01-系统设计说明书.docx --toc

# 2. DOCX → PDF（更新目录域与页码，导出带书签的 PDF）
powershell -File tools/docx2pdf.ps1 `
  -Docx "docs/01-系统设计说明书.docx" `
  -Pdf  "docs/01-系统设计说明书.pdf"
```

两步必须按顺序执行。跳过分词第 2 步导出的 PDF，目录会是一行占位文字。

## 排版约定

| 元素 | 规格 |
|---|---|
| 纸张与页边距 | A4，上下 2.54cm，左 3.0cm，右 2.5cm |
| 正文 | 宋体/Times New Roman，小四 12pt，1.5 倍行距，首行缩进 2 字符 |
| 一级标题 | 黑体 16pt 居中，段前分页 |
| 二级标题 | 黑体 14pt |
| 三级标题 | 黑体 12pt |
| 表格 | 五号 10.5pt（≥6 列降为 9pt），表头加粗浅灰底、跨页重复、行不跨页断开 |
| 代码块 | Consolas 9pt，浅灰底，不缩进 |
| 图片 | 居中，宽度不超过版心，高度上限 19cm（避免竖长流程图撑破整页） |
| 图注 | 五号居中，紧跟图片 |
| 图占位 | 浅黄底居中框，标注缺图文件路径 |
| 引用块 | 浅灰底 + 左侧竖线，用于设计说明与决策理由 |
| 页脚 | 居中页码 |

## 两个已知的排版事实

1. **列宽按内容分配，不平均分**。平均分配会把「修订内容」这类长文本列压成竖条，
   行高撑到整页。分配算法见 `_column_widths()`：取该列最大显示宽度与平均宽度的
   较大者，开 0.72 次方抑制极端列独占宽度，再归一化到版心。
2. **章标题用「段前分页」而非插入分页符**。插入分页符在前一页恰好排满时会产生
   整页空白，段前分页不会。

## 内容写作上的两个约束（工具会放大其后果）

- **表格里的长英文标识符**（如 `compare_products`）在窄列中会被拆成两行，
  技术读者易误读。写文档时尽量让列宽与标识符长度匹配。
- **引用块内嵌套表格**是支持的，但分隔行 `|---|` 会被工具自动剔除。
  引用块内不要嵌套代码块与图片，这两类未做支持。

## 重新生成后必须复核的三处

1. 目录页码与实际章节页码是否一致（Word 更新域后自动重算，但需肉眼确认）
2. 图片是否都有替换为实际 PNG（未交付的图会显示为浅黄占位框）
3. 页数变化后，是否有只有一两行内容的「孤页」——出现时优先微调该章文字，
   而不是缩小行距
